# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions will follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Urd is pre-release: no version has been published yet, and the entries below describe the current state of the repository, not a release.

## Unreleased

### Renamed to Urd

- **The project is now Urd, at `github.com/getsyntegrity/urd`.** Every module path changed its prefix from `github.com/getsyntegrity/ego`; the `engine` package and its API are unchanged, and there is still no root package. Rewrite imports with the command in [`MIGRATION.md`](./MIGRATION.md). The first release under the new path is `v0.1.0`.
- **Publisher IDs and the Kafka client ID are now `urd-*`.** `ID()` returns `urd-kafka`, `urd-nats`, `urd-pulsar` and `urd-websocket`; the Kafka `ClientID` is `urd-kafka-publisher`.
- **Free-text error messages start with `urd:`** instead of `ego:` or `eGo:`. The concurrency-conflict grammar `ego: concurrency conflict: grammar=v1` is unchanged because callers parse it.
- **`URD_TELEMETRY_CONTRACT_DUMP` replaces `EGO_TELEMETRY_CONTRACT_DUMP`.** The old name is still read as a fallback and is deprecated.
- **Internal identifiers and doc comments no longer say `ego`.** Persisted and wire-level names (`egopb`, `ego.*` metadata keys, GoAkt extension IDs, NATS stream names, `ego_schema_migrations`) keep their spelling on purpose; see [`MIGRATION.md`](./MIGRATION.md).

### Breaking changes

- **OpenTelemetry metric, span and attribute names changed from `ego.*` to `urd.*`.** Tracer and meter scope names changed with them. Dashboards and alerts must use the new names (Prometheus: `urd_commands_total`, and so on); the old-to-new table is in [`MIGRATION.md`](./MIGRATION.md).
- **The root module path is `github.com/getsyntegrity/ego`, with no `/vN` suffix.** A path without a suffix carries `v0` and `v1` versions only. Publisher modules keep their own paths, `github.com/getsyntegrity/ego/publisher/<name>` (`kafka`, `nats`, `pulsar`, `websocket`). In the repository the nested modules require the root at the development placeholder `v0.0.0`, resolved through a local `replace` directive; `v0.0.0` is not a tag and is not installable.
- **The root package moved to `github.com/getsyntegrity/ego/engine` (package `engine`).** The module root holds no Go files. Replace the import path and the qualifier: `ego.NewEngine` is `engine.NewEngine`, `ego.EventSourcedBehavior` is `engine.EventSourcedBehavior`, and so on; no symbol was renamed, added or removed. A local variable named `engine` shadows the package after its declaration, so rename the variable or alias the import. `archcheck` enforces the empty root with a `root-no-go-files` check.
- **Generated protobuf code carries the new package path.** `egopb` and `test/data/testpb` were regenerated with `protoc-gen-go` v1.36.12 (never text-edited: `go_package` sits inside the serialized descriptor).
- **`persistence/conformance` no longer depends on `github.com/stretchr/testify` (action required if you call a `Check` directly).** The exported field `Check[S].Run` changed from `func(ctx context.Context, t require.TestingT, store S)` to `func(ctx context.Context, t conformance.TestingT, store S)`, and so did `EventsStoreChecks`, `StateStoreChecks` and `SnapshotStoreChecks`. `conformance.TestingT` is a new interface with `Errorf(format string, args ...any)`, `FailNow()` and `Helper()`; `*testing.T` satisfies it. Nothing changes if you only call `RunEventsStoreConformance`, `RunStateStoreConformance`, `RunSnapshotStoreConformance` or the `Capture*StoreChecks` functions. If you call `check.Run(ctx, t, store)` with a `*testing.T`, it still compiles. If you wrote your own `Check` or passed a value typed `require.TestingT`, change the parameter type to `conformance.TestingT`. Failure text, including `CheckResult.Errors`, is now `<rule>: <expected/actual>` instead of testify's `Error Trace` blocks.

- **In a multi-tenant engine an actor is identified by (tenant, entity ID), not by the entity ID alone (#97, EGO-TENANT-009).** Two tenants that use the same ID now get two independent actors with independent state, instead of the second tenant being refused with `ErrSpawnTenantMismatch`. The business ID and the persistence ID are unchanged; only the GoAkt actor name differs. Spawn, `Dispatch`/`SendCommand`, `SagaStatus`, `EntityExists`, the commands a saga sends to its entities and relocation all derive the name from one function, `internal/actoridentity.Qualify`, which encodes the tenant so no tenant or ID can collide with another. An actor checks that its name matches its tenant and ID before it reads a store, so an actor relocated to another node recovers from the right tenant's scope. Legacy mode (no resolver) and single-tenant mode (`tenancy.WithSingleTenant`) keep the bare entity ID as the actor name, so existing names, lookups and cluster placement do not change. **Action required only if you look an entity up by its GoAkt actor name** (for example `ActorSystem.ActorOf(ctx, id)`) in an engine with a multi-tenant resolver: use `Engine.EntityExists`, which resolves the caller's tenant, instead. Not covered: a command sent to an actor on another node still arrives without the caller's tenant identity, as before this change (#305).

- **An event-sourced entity no longer answers a command it did not run, and no longer runs the command it was persisting a second time (#97).** While an entity waits for a write to be confirmed it stashes the command that caused it, and it answers that command once the confirmation arrives. GoAkt re-delivers a stashed message at the tail of the mailbox, not at the head as its documentation says, so a command that was already queued behind the confirmation reached the entity first, was answered with the current state without being run, and the stashed command then ran again, which wrote a second, identical event. A saga that credits an account when it sees it created hit this: the credit was acknowledged and lost, and the account's journal held the create twice. The entity now answers only the request whose write it is confirming, told apart by the call that sent it and not by its message, and a restarted entity drops the write its previous run had in flight. This covers entities spawned without `WithBatchThreshold` (the default). The batched path has the same defect and is not covered: see #306.
- **A batched event-sourced entity no longer answers a request with the reply of another, and no longer runs a request twice (#306).** With `WithBatchThreshold`, the entity answered each stashed request with the next precomputed reply to whatever message arrived first, but GoAkt re-delivers stashed messages at the tail of the mailbox, so a command already queued behind the write's confirmation came first: it received another request's reply without running, and the stashed request later ran again as a new command, leaving a duplicate event in the journal. Each batch entry now records the request it answers and only that request receives it; any other command waits in the stash until the batch is answered. Entities without batching are unchanged.
- **An event-sourced entity whose write fails now answers every command that was queued behind it, instead of leaving those callers to their timeout (#307).** When a write fails and the entity cannot tell what the store holds, it stops so that it is rebuilt from the journal. It released the commands waiting in its stash and shut down in the same turn, but GoAkt re-delivers the stash at the tail of the mailbox and `Shutdown` does not process what the mailbox still holds, so those commands were dropped without an answer; each caller waited for its own timeout. This applies with and without `WithBatchThreshold`. The pending requests already received the error of the write; the commands queued behind them now receive the explicit error `entity stopped after a failed write: command not executed`, are not run, and write nothing. A caller that gets this error may resend the command to the rebuilt entity: the entity does not retry it for them. A command that reaches the entity after it has stopped is, as before, a call to a stopped actor.
- **An event stream subscriber no longer stops receiving events, and the publisher no longer hangs, when a producer is slow to finish a publish (#308).** The queue behind each subscriber recycled its dequeued nodes through a `sync.Pool`. A producer that was still holding the node a consumer had just dequeued could then link its event to a node that was no longer in the queue, or to itself, so the event was lost or `Publish` spun forever in `Queue.Enqueue`. An entity writing through that publisher never got the confirmation of its write, and its command timed out. Nodes are no longer recycled.
- **Concurrent subscriptions to a new `EventsStream` topic no longer lose subscribers (#97).** `Subscribe` read the topic and created it as two steps, so two subscribers arriving together at a topic nobody had subscribed to each created its map and the second replaced the first; the first never received an event. `Subscribe`, `Unsubscribe` and `Close` now change the topic bookkeeping under one lock.
- **Stopping or restarting a saga no longer panics (#97).** The saga's stop channel was created only by its constructor, so a saga that GoAkt had relocated to another node (built from its registered type, not through the constructor) panicked in `PostStop` with `close of nil channel`, and a restarted saga reused a channel the previous run had already closed. Each run of the saga now has its own stop signal, which its event-consuming goroutine receives as an argument.

- **GoAkt is pinned to an unreleased commit, `v4.5.7-0.20261001174708-cf9c8659f741`, in the root module and in `benchmark`, `test/compat`, `example` and `inttest` (#97).** v4.5.6 (the latest release) has a defect that stops a whole actor system at random: `GoAktUserGuardian` panics when it processes a child's `*Terminated` before its own `*PostStart`, and the root guardian then shuts the system down. It showed up as a flaky `TestEventSourcedActor/with_state_recovery_from_event_store` on `develop` too (9 failures in 3600 runs under load on v4.5.6, 0 in 3600 on the pinned commit). It is fixed upstream in Tochemey/goakt#1424, merged on 2026-10-01 and not yet in a release. The pin is the merge commit of that fix, not the tip of `main`, but it also brings the 31 upstream commits between v4.5.6 and it (grains, cluster registry and actor-name handling, remote listen address, dependency upgrades). Return to a tagged release as soon as one contains #1424.

### Release process

- **Retired tag names must never be reused.** `v4.0.0`, `publisher/kafka/v0.1.0`, `publisher/nats/v0.1.0`, `publisher/pulsar/v0.1.0` and `publisher/websocket/v0.1.0` were published, then withdrawn. The Go module proxy and checksum database keep their old content, so a different tag with the same name would be a checksum mismatch for consumers. They are listed in `scripts/ci/retired-tags.txt`; `internal/cmd/releaseplan` refuses to plan or accept them, and `release.yml` and `release-publishers.yml` check the list before doing anything.
- **`release.yml` waits for `sum.golang.org`, not only the proxy, before the publisher bump (#189).** The wait is now `internal/cmd/modwait`: it verifies a version through the same public path `go get` uses, retries transient failures (404, 5xx, 429, network) up to a timeout, fails at once on permanent ones (410, checksum mismatch, wrong module path) and explains how to resume with "Re-run failed jobs". See `docs/ci.md`.
- **`releaseplan` ignores, and reports, tags whose major version is not legal for a module's current path** instead of refusing the whole plan.
- **`release-publishers.yml` defaults `bump` to `minor`.** A suffix-less publisher with no tag starts from `v0.0.0`, so the default gives it `v0.1.0`, never `v0.0.1` (a retired name today: choose another bump or version until the maintainers decide the first release).
