# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions will follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Urd is pre-release: no version has been published yet, and the entries below describe the current state of the repository, not a release.

## Unreleased

### Renamed to Urd

- **The project is now Urd, at `github.com/getsyntegrity/urd`.** Every module path changed its prefix from `github.com/getsyntegrity/ego`; the `engine` package and its API are unchanged, and there is still no root package. Rewrite imports with the command in [`MIGRATION.md`](./MIGRATION.md). The first release under the new path is `v0.1.0`.
- **Publisher IDs and the Kafka client ID are now `urd-*`.** `ID()` returns `urd-kafka`, `urd-nats`, `urd-pulsar` and `urd-websocket`; the Kafka `ClientID` is `urd-kafka-publisher`.
- **Free-text error messages start with `urd:`** instead of `ego:` or `eGo:`. The concurrency-conflict grammar `ego: concurrency conflict: grammar=v1` is unchanged because callers parse it.
- **`URD_TELEMETRY_CONTRACT_DUMP` replaces `EGO_TELEMETRY_CONTRACT_DUMP`.** The old name is still read as a fallback and is deprecated.
- **Internal identifiers and doc comments no longer say `ego`.** Persisted and wire-level names (`egopb`, `ego.*` metadata keys, GoAkt extension IDs, NATS stream names, `ego_schema_migrations`) keep their spelling on purpose; see [`MIGRATION.md`](./MIGRATION.md).

### Breaking changes

- **OpenTelemetry metric, span and attribute names changed from `ego.*` to `urd.*`.** Tracer and meter scope names changed with them. Dashboards and alerts must use the new names (Prometheus: `urd_commands_total`, and so on); the old-to-new table is in [`MIGRATION.md`](./MIGRATION.md).
- **The root module path is `github.com/getsyntegrity/ego`, with no `/vN` suffix.** A path without a suffix carries `v0` and `v1` versions only. Publisher modules keep their own paths, `github.com/getsyntegrity/ego/publisher/<name>` (`kafka`, `nats`, `pulsar`, `websocket`). In the repository the nested modules require the root at the development placeholder `v0.0.0`, resolved through a local `replace` directive; `v0.0.0` is not a tag and is not installable.
- **The root package moved to `github.com/getsyntegrity/ego/engine` (package `engine`).** The module root holds no Go files. Replace the import path and the qualifier: `ego.NewEngine` is `engine.NewEngine`, `ego.EventSourcedBehavior` is `engine.EventSourcedBehavior`, and so on; no symbol was renamed, added or removed. A local variable named `engine` shadows the package after its declaration, so rename the variable or alias the import. `archcheck` enforces the empty root with a `root-no-go-files` check.
- **Generated protobuf code carries the new package path.** `egopb` and `test/data/testpb` were regenerated with `protoc-gen-go` v1.36.12 (never text-edited: `go_package` sits inside the serialized descriptor).
- **`persistence/conformance` no longer depends on `github.com/stretchr/testify` (action required if you call a `Check` directly).** The exported field `Check[S].Run` changed from `func(ctx context.Context, t require.TestingT, store S)` to `func(ctx context.Context, t conformance.TestingT, store S)`, and so did `EventsStoreChecks`, `StateStoreChecks` and `SnapshotStoreChecks`. `conformance.TestingT` is a new interface with `Errorf(format string, args ...any)`, `FailNow()` and `Helper()`; `*testing.T` satisfies it. Nothing changes if you only call `RunEventsStoreConformance`, `RunStateStoreConformance`, `RunSnapshotStoreConformance` or the `Capture*StoreChecks` functions. If you call `check.Run(ctx, t, store)` with a `*testing.T`, it still compiles. If you wrote your own `Check` or passed a value typed `require.TestingT`, change the parameter type to `conformance.TestingT`. Failure text, including `CheckResult.Errors`, is now `<rule>: <expected/actual>` instead of testify's `Error Trace` blocks.

- **In a multi-tenant engine an actor is identified by (tenant, entity ID), not by the entity ID alone (#97, EGO-TENANT-009).** Two tenants that use the same ID now get two independent actors with independent state, instead of the second tenant being refused with `ErrSpawnTenantMismatch`. The business ID and the persistence ID are unchanged; only the GoAkt actor name differs. Spawn, `Dispatch`/`SendCommand`, `SagaStatus`, `EntityExists`, the commands a saga sends to its entities and relocation all derive the name from one function, `internal/actoridentity.Qualify`, which encodes the tenant so no tenant or ID can collide with another. An actor checks that its name matches its tenant and ID before it reads a store, so an actor relocated to another node recovers from the right tenant's scope. Legacy mode (no resolver) and single-tenant mode (`tenancy.WithSingleTenant`) keep the bare entity ID as the actor name, so existing names, lookups and cluster placement do not change. **Action required only if you look an entity up by its GoAkt actor name** (for example `ActorSystem.ActorOf(ctx, id)`) in an engine with a multi-tenant resolver: use `Engine.EntityExists`, which resolves the caller's tenant, instead. Also fixes a crash that predates this change: stopping a saga that GoAkt had relocated to another node panicked in `PostStop` (`close of nil channel`), because the saga's stop channel was created only by its constructor and a relocated actor is built from its registered type. Not covered: a command sent to an actor on another node still arrives without the caller's tenant identity, as before this change (#305).

### Release process

- **Retired tag names must never be reused.** `v4.0.0`, `publisher/kafka/v0.1.0`, `publisher/nats/v0.1.0`, `publisher/pulsar/v0.1.0` and `publisher/websocket/v0.1.0` were published, then withdrawn. The Go module proxy and checksum database keep their old content, so a different tag with the same name would be a checksum mismatch for consumers. They are listed in `scripts/ci/retired-tags.txt`; `internal/cmd/releaseplan` refuses to plan or accept them, and `release.yml` and `release-publishers.yml` check the list before doing anything.
- **`release.yml` waits for `sum.golang.org`, not only the proxy, before the publisher bump (#189).** The wait is now `internal/cmd/modwait`: it verifies a version through the same public path `go get` uses, retries transient failures (404, 5xx, 429, network) up to a timeout, fails at once on permanent ones (410, checksum mismatch, wrong module path) and explains how to resume with "Re-run failed jobs". See `docs/ci.md`.
- **`releaseplan` ignores, and reports, tags whose major version is not legal for a module's current path** instead of refusing the whole plan.
- **`release-publishers.yml` defaults `bump` to `minor`.** A suffix-less publisher with no tag starts from `v0.0.0`, so the default gives it `v0.1.0`, never `v0.0.1` (a retired name today: choose another bump or version until the maintainers decide the first release).
